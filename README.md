# Position Drill

A static GitHub Pages app for drilling backgammon checker-play and cube-decision errors from Extreme Gammon (`.xg` / `.xgp`) files.

## Repository structure

Position Drill is self-contained in one repository.

- `imports/` — source XG/XGP match files
- `scripts/build.py` — **the only build script**
- `vendor/xgread/` — bundled XG reader
- `LICENSES/` — third-party license notices
- `config.json` — build thresholds and display metadata
- `index.html`, `app.js`, `styles.css` — web UI
- `.github/workflows/deploy.yml` — GitHub Pages build/deploy workflow

`dist/` is generated by the build and must not be committed. Python `__pycache__/` / `.pyc` files are also generated files and must not be committed.

## Position types

- **Checker Play**
- **Double Action**
- **Take Action**

The player displayed on the bottom side in the source XG file is the drill owner ("me").

Cube-decision display convention:

- Double Action: black/bottom = drill owner/doubler
- Take Action: black/bottom = drill owner/cube receiver; white/top = doubler/on-roll
- Double Action and Take Action diagrams/game information show the state **immediately before the cube offer**
- Take/Pass analysis retains the offered-cube response data internally

## Filters

### Task

A position is included when either condition is true:

- Correct count is 0
- Correct count is lower than incorrect count

### New

`New` is calculated during the GitHub Actions build from the XG file's latest Git upload/update time.

- Window: **7 days**
- A daily scheduled rebuild runs at **03:00 JST**
- The build writes a boolean `isNew` into each generated position

## Progress persistence

Progress is stored locally in the browser.

- Primary storage: `localStorage`
- Mirror/restore storage: IndexedDB
- Stable progress keys are preserved across normal rebuilds
- Clearing browser/site data, changing browser/device/origin, or changing the underlying position identity can separate/reset progress

## Build and deployment

Pushes to `main`, manual workflow runs, and the daily schedule run `.github/workflows/deploy.yml`.

The workflow:

1. Checks out the full Git history (`fetch-depth: 0`)
2. Checks JavaScript/Python syntax
3. Runs `python scripts/build.py`
4. Deduplicates identical parsed matches
5. Validates generated position IDs, decision kinds, image references, error values, New flags, and Take Action cube legality
6. Uploads `dist/` as the GitHub Pages artifact
7. Deploys GitHub Pages

The app checks `data/positions.json` for updates every five minutes while open and again when the tab becomes active.

## Local checks

```bash
node --check app.js
python -m py_compile scripts/build.py
python scripts/build.py
```

## Maintenance rules

- Do not add another build script at the repository root. Use `scripts/build.py`.
- Do not commit `dist/`, `__pycache__/`, or `.pyc` files.
- Do not keep two filenames for the same parsed XG match.
- Keep `LICENSES/xgread-LICENSE.txt` while `vendor/xgread/` is bundled.
- Keep the favicon/apple-touch-icon files referenced from `index.html`.
- Preserve the existing browser storage keys unless an intentional migration is implemented.
